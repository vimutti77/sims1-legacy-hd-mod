# แผนงาน

## สรุปเป้าหมาย

ทำให้ The Sims Legacy Collection คมชัดบนจอความละเอียดสูง (1440p, 4K) โดยไม่ต้องลดความละเอียดจอ

**ลำดับ:** UI และตัวหนังสือก่อน (เฟส 0–3) แล้วค่อยทำกราฟิกในบ้าน (เฟส 4)

- UI แก้ปัญหาที่ผู้เล่นบ่นมากที่สุด และใช้พิสูจน์ H4 ไปในตัว
- Sprite ยากกว่ามาก (มีช่องสี + alpha + z-buffer ที่ต้องขยายให้สอดคล้องกัน) จึงไม่ควรลงแรงก่อนรู้ผล H4

## สมมติฐานที่ต้องพิสูจน์

| # | สมมติฐาน | ถ้าไม่จริง |
|---|---|---|
| H1 | UI layout เก็บเป็นไฟล์ข้อมูลที่แก้ได้ ไม่ได้ฝังใน exe | ต้องแพตช์ exe ทั้งหมด → น่าจะ **หยุด** |
| H2 | UI bitmap เก็บในไฟล์ที่แกะ/แทนที่ได้ (FAR, IFF, BMP) | **หยุด** |
| H3 | เกมอ่านไฟล์ที่แก้แล้ว ไม่มี checksum หรือดึงไฟล์เดิมคืน | หาวิธีเลี่ยง หรือ **หยุด** |
| H4 | บังคับให้เกมวาด UI ที่สเกล 1:1 บนจอ 4K ได้ (config, registry, command-line หรือแพตช์ exe จุดเดียว) | **ตัวบล็อกหลัก** ถ้าไม่ได้ → **หยุด** |

## Phase 0: Spike (1–2 สุดสัปดาห์)

**เป้าหมาย:** ตอบ H1–H4 ให้ได้ ยังไม่เขียน patcher

- [x] เขียนผลลง `docs/FINDINGS.md`

### เกณฑ์ Go / No-go

- **Go:** H1–H3 จริง และ H4 ทำได้โดยไม่ต้องแพตช์ exe หรือแพตช์แค่จุดเดียวที่หาเจอได้ด้วย string/pattern
- **Go แบบมีเงื่อนไข:** H4 ต้อง reverse-engineer ด้วย Ghidra/x64dbg → ประเมินเวลาใหม่ และยอมรับว่าแพตช์อาจพังเมื่อ EA อัปเดต
- **No-go:** H1 หรือ H2 ไม่จริง หรือ H4 ทำไม่ได้หลังลองครบ → ใช้ launcher ใน `launcher/` เป็นทางแก้ถาวร

## Phase 1: Proof of concept

- เลือกหน้าจอเดียว (control panel ด้านล่างในโหมด Live)
- upscale bitmap 2× (เริ่มจาก nearest-neighbor เพื่อเช็กตำแหน่ง แล้วค่อยลอง xBRZ หรือ AI upscaler)
- คูณพิกัด layout 2×
- **ผ่านเมื่อ:** หน้าจอนั้นคมที่ 4K และคลิกปุ่มได้ถูกตำแหน่ง

## Phase 2: Patcher tool

- ~~โปรแกรมที่อ่านไฟล์ในเครื่องผู้ใช้ → upscale → เขียนกลับ~~ เปลี่ยน (2026-10-22, ผู้ใช้ตัดสินใจ): แจกไฟล์สำเร็จ (vkproxy + pack HD + รายการต่างๆ ที่สร้างบนเครื่องนี้) แยกจาก repo เช่นเป็นไฟล์ของ release เพราะเครื่องผู้เล่นทั่วไปรัน AI/ตัวสร้างไม่ไหว; repo เก็บเฉพาะโค้ดที่ใช้สร้าง mod ไม่มีไฟล์จากเกม
- ~~ตัวติดตั้งวางไฟล์ลงโฟลเดอร์เกม พร้อมสำรองและถอนออกได้~~ เปลี่ยน (2026-10-23): แจกบน Nexus Mods (ผู้ใช้ตัดสินใจ) เป็น 7z แยกชุด (core, objects, walls, sims, portraits) วางโครงตรงกับโฟลเดอร์เกม แตกลงโฟลเดอร์เกมเลย ไม่มีตัวติดตั้ง แบบเดียวกับ mod แทน DLL ตัวอื่น: mod ไม่ทับไฟล์ใดของเกม (`vulkan-1.dll` ไม่มีในโฟลเดอร์เกม) จึงไม่ต้องสำรอง ถอนออก = ลบ `vulkan-1.dll` กับโฟลเดอร์ `vkproxy`; `tools/release.py` จัดไฟล์ (pack ใหม่ต่อชุด เลข pack ไม่ชนกัน, คัดภาพหัวของ Sim ในเซฟผู้สร้างออก) DLL แบบ release (`build.ps1 -Release`: ไม่มีปุ่มและไฟล์ debug) README ผู้เล่น `docs/README_players.txt`
- สิ่งที่ต้องเกิดตอนเล่นบนเครื่องผู้เล่น (เช่นภาพหัวของ Sim ที่สร้างทีหลัง) ต้องทำใน vkproxy ด้วยข้อมูลที่แจกไป
- ความละเอียด: ไฟล์ HD ชุดเดียว (3×) ใช้ได้ทุกเท่า (1440p/1600p = 2×, 5K = 4×: proxy ย่อ/ขยายตอนอ่าน) แค่ฟอนต์ต้องสร้างต่อเท่า; 1080p ไม่ได้อะไร

## Phase 3: ครอบคลุมทั้งเกม

- ทุกหน้าจอ รวม expansion ทั้ง 7 ชุด
- ฟอนต์: ภาค 1 น่าจะใช้ bitmap font → ต้องทำชุดใหม่ที่ขนาด 2×
- ทดสอบ regression หลัง EA ออกแพตช์

## Phase 4: กราฟิกในบ้าน (หลัง UI เสร็จ)

แยกเป็น 2 ส่วน เพราะธรรมชาติต่างกัน:

**4a. Sims (คน):** เป็นโมเดล 3D ที่เรนเดอร์สด มีแค่ texture ผิว/เสื้อผ้าเป็น bitmap → upscale texture อย่างเดียวอาจพอ น่าจะทำได้ง่ายกว่า

**4b. Object / กำแพง / พื้น (SPR2):** ภาพวาดล่วงหน้า 3 ระดับซูม

- Spike ก่อน: เกมรับ sprite ที่ใหญ่กว่าเดิมได้หรือไม่ หรือขนาด sprite ผูกกับ tile grid ตายตัว
- upscale ช่องสีด้วย AI upscaler, ช่อง alpha และ z-buffer ด้วย nearest-neighbor หรือวิธีที่รักษาขอบ แล้วเช็กว่าการบังกันยังถูกต้อง
- ทำ pipeline อัตโนมัติ เพราะมี object หลายพันชิ้นรวม expansion
- เกณฑ์ go/no-go แยกต่างหาก: ถ้าเกมไม่รับ sprite ขนาดใหม่ → หยุดแค่ UI

## ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| H4 ทำไม่ได้ | ทั้งโปรเจกต์ | Phase 0 จำกัดเวลา, มี launcher เป็นแผนสำรอง |
| EA อัปเดตแล้วแพตช์พัง | ต้องตามแก้ทุกครั้ง | ใช้ pattern แทน offset ตายตัว, patcher เช็กเวอร์ชันก่อนแพตช์ |
| งาน asset หลายร้อยหน้าจอ | เวลานาน | ทำ pipeline upscale อัตโนมัติ, แก้มือเฉพาะจุดที่จำเป็น |
| ลิขสิทธิ์ | แจกจ่ายไม่ได้ | แจกเฉพาะ patcher ไม่แจก asset |
